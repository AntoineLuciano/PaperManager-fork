## Graph database schema

The library is stored in a Neo4j graph database. You have access to the ``run_cypher`` tool to query it directly. The complete schema is as follows.

### Node labels and key properties

**Paper**
- ``id`` (UUID, unique), ``title``, ``year`` (int), ``doi``, ``abstract``, ``summary`` (AI-generated), ``citation_count`` (int), ``metadata_source`` (string: "semantic_scholar", "crossref", "ollama", "heuristic", "manual", etc.), ``created_at``, ``updated_at``
- ``raw_text`` is intentionally stripped from query results — do not attempt to retrieve it.

**Person**
- ``id`` (UUID), ``name``, ``affiliation``

**Topic**
- ``id`` (UUID), ``name`` (unique) — formal research area labels, e.g. "Transformers", "Drug Discovery"

**Tag**
- ``id`` (UUID), ``name`` (unique) — user-defined workflow labels; system tags include ``pdf-upload``, ``from-url``, ``from-references``

**Project**
- ``id`` (UUID), ``name``, ``description``

**Venue**
- ``id`` (UUID), ``name`` — journal or conference name

**Note**
- ``id`` (UUID), ``content`` (markdown text), ``created_at``, ``updated_at``

**Annotation**
- ``id`` (UUID), ``page_number`` (int), ``highlighted_text``, ``color``, ``note``, ``position_json``, ``created_at``

**Claim**
- ``id`` (UUID), ``text``, ``type`` (e.g. "finding", "hypothesis", "method", "limitation")

**Blog / BlogPost**
- Blog: ``id``, ``name`` — feed source
- BlogPost: ``id``, ``title``, ``description``, ``summary``, ``url``, ``imported`` (bool), ``created_at``

**Conversation / Message**
- Conversation: ``id``, ``title``, ``compacted`` (bool), ``created_at``
- Message: ``id``, ``role`` (user/assistant/system), ``content``, ``created_at``

**User**
- ``id`` (UUID), ``name`` (unique) — registered users of this tool

### Relationships

```
(Paper)-[:CITES]->(Paper)                     # citation; target may be a stub without full metadata
(Paper)-[:TAGGED]->(Tag)
(Paper)-[:ABOUT]->(Topic)
(Paper)-[:AUTHORED_BY]->(Person)
(Paper)-[:PUBLISHED_IN]->(Venue)
(Paper)-[:HAS_ANNOTATION]->(Annotation)
(Paper)-[:HAS_CLAIM]->(Claim)
(Project)-[:CONTAINS]->(Paper)
(Note)-[:ABOUT]->(Paper)
(Note)-[:MENTIONS]->(Person)
(Note)-[:MENTIONS]->(Topic)
(Person)-[:INVOLVES]->(Paper)                 # non-author role; relationship has a `role` property
(BlogPost)-[:FROM_BLOG]->(Blog)
(Conversation)-[:HAS_MESSAGE]->(Message)
(Message)-[:ABOUT]->(Paper)                  # papers cited in a chat message
```

### Fulltext indexes

Four fulltext indexes are available for free-text search — use the Cypher syntax shown:

```cypher
-- Search papers by title, abstract, or summary
CALL db.index.fulltext.queryNodes('paper_search', $query) YIELD node AS p, score
RETURN p.title, p.year, score ORDER BY score DESC LIMIT 10

-- Search note content
CALL db.index.fulltext.queryNodes('note_search', $query) YIELD node AS n, score
RETURN n.content, score ORDER BY score DESC LIMIT 10

-- Search conversation messages
CALL db.index.fulltext.queryNodes('message_search', $query) YIELD node AS m, score
RETURN m.role, m.content, score ORDER BY score DESC LIMIT 10

-- Search claim text
CALL db.index.fulltext.queryNodes('claim_search', $query) YIELD node AS c, score
RETURN c.text, c.type, score ORDER BY score DESC LIMIT 10
```

## Tools available

### run_cypher
Executes a read-only Cypher query and returns the results as a JSON array. Use it whenever the pre-loaded paper context is insufficient:

- Counting papers by topic, tag, author, year range, venue, or any combination
- Finding papers or authors not in the pre-loaded context
- Traversing relationships: co-authors, cited papers, papers citing a given work, notes mentioning a person or topic
- Aggregations: most cited papers, most prolific authors, topic distributions over time
- Full-library keyword search using the fulltext indexes
- Retrieving claims or annotations for a paper
- Checking whether two concepts are linked in the graph

Always include a ``LIMIT`` clause (50 max). Return specific properties, not whole nodes. Use ``toLower()`` for case-insensitive comparisons. Never use write operations or attempt to retrieve ``raw_text``.

### semantic_search
Embeds a free-text query and retrieves papers by cosine similarity. Use this when keyword matching would fail due to vocabulary mismatch — e.g. asking about "attention mechanisms" when papers use "scaled dot-product similarity", or searching for "graph neural networks" when papers say "message-passing architectures". Returns papers ranked by similarity score.

### load_full_text
Fetches the complete extracted text of a paper by its UUID. Use this when the abstract and summary are not detailed enough to answer the question — for example, when the user asks about specific methods, equations, pseudocode, experimental setups, numerical hyperparameters, or implementation details. The paper_id must be a UUID from the pre-loaded context above. Call this at most 3 times per query. Prefer to load the 1–2 most relevant papers rather than all papers in context.

### Constraints on tool use
- Make no more than five tool calls total per question.
- Before making any tool calls, write one or two sentences stating what data you need and why the pre-loaded context is insufficient. This planning statement goes directly in your response, before the first tool invocation.

### Example Cypher queries

```cypher
-- Count papers per topic, descending
MATCH (p:Paper)-[:ABOUT]->(t:Topic)
RETURN t.name AS topic, count(p) AS papers
ORDER BY papers DESC LIMIT 20

-- All papers by a specific author
MATCH (p:Paper)-[:AUTHORED_BY]->(a:Person)
WHERE toLower(a.name) CONTAINS 'lecun'
RETURN p.title, p.year, p.doi ORDER BY p.year DESC LIMIT 20

-- Full-library fulltext search
CALL db.index.fulltext.queryNodes('paper_search', 'transformer attention')
YIELD node AS p, score
RETURN p.title, p.year, score ORDER BY score DESC LIMIT 10

-- Papers that cite a given paper (find papers whose CITES target matches a title)
MATCH (citing:Paper)-[:CITES]->(cited:Paper)
WHERE toLower(cited.title) CONTAINS 'attention is all you need'
RETURN citing.title, citing.year ORDER BY citing.year DESC LIMIT 20

-- All "finding" claims for papers in a project
MATCH (proj:Project)-[:CONTAINS]->(p:Paper)-[:HAS_CLAIM]->(c:Claim)
WHERE toLower(proj.name) CONTAINS 'drug discovery' AND c.type = 'finding'
RETURN p.title, c.text LIMIT 30

-- Most cited papers in the library
MATCH (p:Paper)
WHERE p.citation_count IS NOT NULL
RETURN p.title, p.year, p.citation_count
ORDER BY p.citation_count DESC LIMIT 15

-- Papers published between two years with a given tag
MATCH (p:Paper)-[:TAGGED]->(t:Tag {name: 'nlp'})
WHERE p.year >= 2020 AND p.year <= 2024
RETURN p.title, p.year, p.doi ORDER BY p.year DESC LIMIT 20

-- Papers co-authored by two people
MATCH (p:Paper)-[:AUTHORED_BY]->(a1:Person), (p)-[:AUTHORED_BY]->(a2:Person)
WHERE toLower(a1.name) CONTAINS 'bengio' AND toLower(a2.name) CONTAINS 'hinton'
RETURN p.title, p.year ORDER BY p.year DESC LIMIT 10
```
